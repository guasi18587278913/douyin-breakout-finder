# 轻量网站第一版

用户于2026-10-10明确要求开始网站、完成相关优化、使用自己的服务器部署，最终交付固定网址验收。新网站是主入口，Skill保留为可选入口，两者复用同一套搜索、核验、报告与独立验证代码。

## 交付范围

- 固定HTTPS地址 `breakout.zmtgzt.com`，部署在已有香港服务器 `topic-remix`，独立系统用户、进程、数据目录和Caddy站点文件。
- 邀请注册与登录、主题输入、后台研究任务、逐批合格作品、完成报告、历史记录、离线接续、退出登录。
- 管理员可创建邀请并管理后台服务配置。普通用户不接触TikHub Key、模型Key、Python或CLI。
- 首版为受邀请的验收版本；不接支付、不自动收费或开放无限注册，不因网站上线改变研究标准。
- TikHub每轮仍最多50次、USD0.50预留；模型单轮预留上限USD0.15，最多3次格式修复。任务逐用户隔离，每个账户最多一个进行中的任务，服务器一次执行一个研究任务。
- 模型使用服务端HTTP接口；不把本机Codex登录文件或个人会话上传服务器。复用现有TikHub/DeepSeek服务配置与一次真实验收的授权单独询问，未获得前使用合成数据检查，继续其他实现。
- 访问邀请码、登录会话、配置密钥和研究文件分别保存，不进源码、前端静态资源或日志。生产Cookie仅HTTPS，状态修改校验Origin与CSRF。
- 不自动恢复中断时的收费搜索。重启后中断任务显示可接续；接续只使用已经保存的数据，缺失数据如实保留。

## 研究优化

接入已实测33条完整返回的新批量统计接口。只在一批多个候选的对照已经准备好时合并缺失ID；缓存先恢复、去重、按最新报价预留，失败不自动改接口重试。少量ID继续使用原统计接口。预算、请求次数和统计尝试追踪覆盖两种接口，不因切换分组绕过限制。

保留增量语义审核、已核验结果先显示、报告具体校验反馈、原样稿写法和独立完成判定。模型和接口的费用、尝试与耗时分别留痕，不能将单接口1.554秒称为整轮研究耗时。

## 部署和验证

应用监听本机独立端口8795，经现有Caddy提供HTTPS；只新增自己的站点文件，校验后reload，不覆盖全局配置。数据使用独立SQLite数据库和私密运行目录；新服务不修改其他网站数据库或配置。

先验证登录/CSRF、两账户数据隔离、任务限额、取消/中断恢复、报告完整性与手机布局；做独立审查并修复阻塞，再部署确定提交。公网先用合成数据走完整流程，再在授权费用内做一次真实研究。部署失败保留旧版本与数据，不能通过清空数据库恢复。
