# 本轮意见处理记录

日期：2026-10-10。外部审查基于70683d1，本轮实现基于后续bf34dfc；逐项对照源码，不把建议直接当作已经证实的性能结论。

| 意见 | 本轮处理 | 证据与剩余范围 |
| --- | --- | --- |
| 实际入口与源码不一致，仍宣布完成 | 增加完整交付检查器与报告独立验证 | 源码、安装、启动指纹、实时磁盘、HTTP报告及浏览器分别核对；缺证据失败 |
| 补搜重复审核旧候选 | 改为增量审核 | 20+10+10条输入只产生40条次审核，保留40条总候选；条件、正文证据或候选内容改变会重审 |
| 模型校验反馈笼统 | 返回固定字段路径和本地规则，带上次答卷供局部修正 | 修复后仍执行整份校验，任意服务商异常原文不回传，最多3次生成 |
| 模型约束比后端宽松 | Schema补齐段落、方法、案例、引用、迁移例子数量边界 | 不改变已认可的文案写法，不保证所有错误都无需返工 |
| 必须等全文写完才能使用 | 逐条核验后在当前进度页显示合格作品和原视频入口 | 写作继续；完成后仍在原标签直接进入报告。重审与播放核验都有效才能展示 |
| 缺少可比较的过程数据 | 扩展timings记录候选数、请求增量、响应缓存命中、模型生成/重试、首条可用结果及总耗时 | 合成测试证明采集机制，未据此承诺真实速度提升 |
| 批量统计接口支持50个ID | 已核对官方OpenAPI和匿名实时报价 | 旧接口USD0.001/最多2条，新接口USD0.025/最多50条。33条合并后旧接口17次USD0.017，新接口一次USD0.025；请求减少不等于更便宜、更快 |
| 接入批量统计并实测 | 等待本次受限付费测试授权 | 提议同一组最多33个已有视频，至多18次、USD0.05，不重新搜索、不自动重试；未通过对照前不替换默认接口 |
| 不同阶段换用更快模型 | 暂不自动更换 | 先保留报告质量，并获得可比的各阶段生成次数和耗时；具体模型选型需要质量对照 |
| 短主题跳过准备生成 | 保留收费前的实际分析握手 | 当前准备步骤还验证分析程序能正常返回；仅检查安装/登录不能证明模型额度和调用可用。不能以省一步为由先收费后发现无法分析 |
| 换框架、多Agent编排 | 不采纳为当前提速方案 | 保持现有有界工作流，不增加模型讨论轮次 |
| 跨研究缓存、连接复用 | 留作后续基于测量的优化 | 需要独立定义采集时间、过期规则与复用边界，当前不扩大 |
| 轻量网站主入口、Skill可选 | 记录为下一产品阶段 | 托管账号、隔离、密钥、计费和部署需单独设计与授权，本轮不建立托管服务 |

官方依据：<https://api.tikhub.io/openapi.json>；匿名报价接口 `/api/v1/tikhub/user/get_endpoint_info`。核对时未携带任何用户Key，未查询视频。报价会变化，正式调用仍应读取当时的官方报价。

搜索覆盖仍按原本最多50次请求、USD0.50预留上限运行，不因凑够3条就结束。外部意见中提出的性能收益，需要真实对照才成立；完成报告不代表已经穷尽所有搜索结果。
