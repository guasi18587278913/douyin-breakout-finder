# 执行与验证分离

执行器产出状态和报告，独立检查器读取实际文件重新判断。检查器不采信手写的 `passed`、报告中的自我评价或另一份副本的截图。

## 报告完成检查

网页在发布新版报告完成状态前运行 `scripts/verification.py` 的只读检查，并保存 `verification.json`：

1. 从本轮已保存的标准化搜索响应重新列出日期范围内的候选 ID，与状态和搜索索引对账。
2. 每条候选都有去向：需审核、排除、待核验、样本有限、未达门槛或合格；记录原因。
3. 对已核验终态重新选择对照、计算播放倍数和资格，包括被标为不合格的作品，防止漏报。
4. 从账本核对请求次数与费用预留；不修改账本、不发起查询。
5. 重新验证保存的报告结构、引用与当前依据，从这些输入只读重建完整 HTML，核对实际文件、可见文字、数值、卡片和链接。

有待核验条目不妨碍交付已核验案例的选题解读；这些条目必须保留在本地记录。`search_exhaustive` 固定为 false，不把有预算和分页限制的研究称为全平台穷尽。缓存是标准化后的公开字段投影，此检查不能证明供应商原始响应没有遗漏。

## 维护者的统一交付入口

使用者仍只需 Python 和 curl。以下浏览器工具只用于维护验收，测试环境需已安装 Playwright 与 Chromium。

先从**实际使用的 Skill 目录**启动，将启动器返回的 JSON 原样保存为一个私密临时文件。它包含会话口令，不应提交、分享或贴进聊天。让该服务生成免费示例，或由维护者挂载已完成且经过复核的缓存报告。不要为了验收自动点击付费开始。

```sh
python3 tests/browser_delivery.py \
  --source '<本轮验收源码目录>' \
  --installed '<实际安装目录>' \
  --ready-file '<启动器返回信息.json>' \
  --out '<本地验收输出目录>'
```

脚本统一核对源码与安装文件、进程启动时冻结的指纹、当前磁盘指纹、服务的运行目录、磁盘报告与 HTTP 实际返回的报告，再用真实浏览器验证完成后直接进入报告、合格图卡、390px 布局、新研究与刷新。最后重新核对输入与报告摘要，防止混用不同版本的证据。

任何一项失败或缺少证据都退出 1；全部通过才退出 0。输出 `acceptance.json`、桌面截图和手机截图，不保存会话口令。仅运行 `scripts/check_delivery.py` 可以检查文件和服务，但不会证明浏览器交互已通过。

验收前后不要修改源码或混用旧进程。更新安装副本前保留备份；重新启动后重新验收。报告以外的本地定制或用户文件不得覆盖。

## 证据适用范围

- 结果绑定本次完整源码文件摘要与运行数据摘要。工作区未提交时明确称为工作区验证，不沿用旧提交的 CI 结论。
- 合成数据只验证流程。真实数据来自缓存时，不能宣称测试过新一轮搜索的耗时或命中率。
- 程序检查不能替代相关性判断、正文事实核查与用户阅读验收；检查器也需要针对漏检的反例测试和独立审查。
- 当前程序没有替用户更换模型、上调预算、触发新查询或部署托管网站。
