## 可以优化的地方与收益边界

### 第一优先级 作者级流水线

当前不同作者虽然有并发，但 `prefetch_histories()` 要等整批历史处理完，`call_many()` 也等待整批结果，才推进后续统计。

本轮有直接证据：“AI做视频！全流程详细拆解”的作者历史在 **12:47:00.900** 已保存，统计却到 **12:47:23.636** 才发起，空等 **22.74 秒**；同批另一作者的慢请求在 12:47:23.574 才结束。

建议让历史已经足够的作者立即进入播放统计，其余作者继续按各自游标翻页。所有请求仍共用总并发上限、各接口限速和预算预留，状态统一合并，不能简单再加一套线程池。

这个例子的统计工作约 **3.23 秒**，有机会移入慢请求的等待窗口。可争取的是重叠这段工作，**不是直接从整轮减掉 22.74 秒**。唯一合格案例自身三页的串行依赖仍然存在。

### 第二优先级 提高有效小号比例并前置明确资格过滤

本轮 48 条候选里，**40 条已知粉丝超过 1 万**。其中 39 条被模型判为相关后，又被程序按粉丝门槛排除；另外 1 条被语义排除，但同样超粉。实际只有 **8 条**来自符合粉丝门槛的账号。

| 关键词 | 候选数 | 符合粉丝门槛 | 最终合格 |
| --- | ---: | ---: | ---: |
| AI自媒体 | 7 | 0 | 0 |
| AI短视频，3 页合计 | 20 | 6 | 0 |
| AI写作 | 7 | 1 | 1 |
| AI视频制作 | 7 | 1 | 0 |
| AI数字人 | 7 | 0 | 0 |

本轮各关键词之间没有重复，按作品 ID 去重后共 48 条。

两个方向值得验证：先把明确超限账号记为资格排除，保留全部 ID、判断指纹与去向，让模型集中处理仍有资格的候选；补搜策略则更多参考每页新增相关小号和合格结果的产出，而不只参考主题相关性。

前者可能减少本轮 10.65 秒语义审核中的部分工作，但不能按减少 83% 候选就承诺减少 83% 时间。后者关系到能否达到 20 条目标：本轮只有 8 条小号候选，即使核验再快，也无法从这批候选得到 20 条合格作品。调整搜索轮次、排序或候选来源需要单独验证检索质量，本轮没有擅自改变策略。

### 第三优先级 连接复用与合适的统计合并

当前数据请求每次启动独立 curl，可以研究同一服务的连接复用。但本轮没有连接和首字节分项计时，不能把 23–29 秒的等待全部归因于握手，也不能先承诺连接复用能省多少秒。

本轮涉及 40 个不同作品的播放统计，却分散在 11、11、10、8 个 ID 的不同工作组中，各批未达到现行 25 个 ID 的批量门槛。可以研究合并已经准备好的独立统计请求，但不能为了凑批次延迟首条结果，也不能用总计 40 个 ID 冒充它们当时同时就绪。

### 较低优先级 封面及本地排版

封面前移并与写作重叠，最多只能覆盖本轮约 1.31 秒的封面阶段。排版与最终核对合计约 0.07 秒，暂时没有优先优化价值。写作和内容审核已经一次通过，取消审核或更换写作方式不能解决本轮主要等待。

下一步应补充连接、首字节及“历史已就绪但统计未开始”的计时，再验证作者级流水线。对外承诺提速前，仍需比较相同预算和资格标准下的等待时间、合格结果数及未解决项，不能用提前停止或丢失案例换取漂亮的秒数。
