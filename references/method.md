# 判断规则与数据格式

## 两阶段语义判断

关键词是搜索假设。先以一页结果判断相关性，再决定保留或扩词。只对实际读过的候选填写标签。搜索按点赞排序，是获取种子的方式；最终播放倍数用单独的统计接口计算。

`review-inbox.json` 是候选 ID 到判断的映射。保留待审条目，修改实际审过的条目：

```json
{
  "1234567890123456789": {
    "decision": "include",
    "reason": "具体讲解FDE如何连接客户的ERP系统，与本轮交付实战范围一致。",
    "priority": 2
  }
}
```

decision 允许 include / exclude / unsure / pending。include、exclude、unsure 必须说明原因。priority 为 1—3，3 最优先；同级按搜索点赞量安排核验。每轮最多处理 `max_candidates` 个满足账号条件的候选，不保证得到相同数量的爆款。

`keyword-quality.json` 的相关率只在已审 include/exclude 中计算。unsure/pending 不进入分母。首次引入量与执行顺序有关；另保留独有结果数。它们是检索诊断，不是平台覆盖率或准确率认证。

## 对照与状态

默认：粉丝上限 10,000；倍数至少 10；搜索近 180 天；目标与对照至少发布 7 天；在目标前后 90 天内选择时间最近的至多 10 条同作者其他作品，最少 6 条。

粉丝上限使用采集时的搜索作者字段；缺失时待核验。只接受作者标识一致的作品。目标必须出现在作者列表里。置顶不因热度高而排除，但置顶日期不能用来判断历史翻页已经覆盖到哪里。

时间排序的列表需要覆盖所需邻域。下列情况可以结束翻页：列表已无下一页；或已翻到比较时间窗下界；或已取得10条近邻且下一页不可能有时间更接近的作品。达到页数/预算上限仍未覆盖时，保留待核验，不用当前随手拿到的10条冒充完整近邻。

- **已核验**：达到倍数、账号符合、历史覆盖足够、目标及全部对照统计完整，且对照达到期望数量。
- **有限样本**：其余条件满足，但实际对照数在最低数量与期望数量之间。
- **待核验**：缺失播放、作者关系未确认、历史不完整、作品太新、对照过少或中位数为零等。
- **未达倍数**：数据完整，但目标/中位数小于设定阈值。
- **未纳入**：账号超出条件，或语义复核排除。

专门统计接口的零值保留；没有 play_count 字段或无效值视为缺失。缺失时不能删除该条对照后重新计算一个更有利的中位数。中位数为零时，倍数留空。

中位数：排序后的中间值；偶数取中间两个数的平均值。目标不参与自身基线。对照不按播放低高筛选。当前实现比较同作者整体邻近作品，并非自动控制同题材或相同发布后时长。

## 配置

使用 `config` 命令生成模板。所有单价默认为 null，需要从 TikHub 当前价目核对后填入。

- `topic`、`scope`、`keywords`：主题、具体纳入边界、初始搜索词。
- `max_followers`、`min_ratio`：账号和倍数门槛。
- `search_days`：实际日期筛选范围。接口仅支持 1、7、180、不限，因此脚本使用覆盖该范围的接口筛选，再本地裁剪。
- `baseline_count`、`min_baseline_count`、`comparison_window_days`、`min_age_days`：比较条件。
- `max_candidates`、`max_search_pages`、`max_author_pages`、`max_requests`：工作量上限。
- `budget_usd`：用户授权的本轮 USD 上限。
- `pricing.usd_per_request`：search/posts/stats/comments 四项 USD 单价。init 前应填齐本轮可能用到的全部项目，建议四项一起核对。评论可不调用，但先记录其价格不产生费用。若初始化时漏填某项，本轮不能再补改配置，需要新建运行目录。
- `pricing.source_url`：官方 TikHub 价目/后台/接口文档地址。
- `pricing.checked_at`：实际核对价格的 ISO 8601 时间，含时区。超过 7 天需重新核对并新建运行。

init 之后配置固定，不能靠修改文件重置费用计数。条件或预算变更时新建目录。过往运行可以离线查看，不自动混入新运行。

本地预算按已核对单价为每次尝试预留。未知计费结果不会自动退回预留；这可能比实际账单更保守。真实支付上限还应由用户的服务商余额和账户限制控制，单价配置错误时本地估算也会错误。

## 可选内容分析格式

只有入选结果可导入分析。不要更改统计字段。

```json
{
  "1234567890123456789": {
    "basis": "title-description",
    "evidence_note": "只读取了标题、描述与第一页评论，未转写原声。",
    "summary": "内容围绕一个ERP建档任务展开。",
    "opening": "先说明业务任务和预期结果。",
    "structure": "人工流程—AI流程—结果检查。",
    "useful_angle": "可以参考具体业务动作的展示方式；不能证明该方式造成播放增长。",
    "comments_summary": "抽样评论询问批量操作和数据准确性。"
  }
}
```

basis 可选 title-description / transcript / video-inspected。必须如实填写 evidence_note。首版脚本不自动转写音频、不自动判断事实真伪。

## 中断与恢复

每次网络请求前先写入费用预留。成功响应经字段投影后原子保存，随后更新状态。缓存命中不产生新请求。若响应已保存但状态写入失败，同一命令会从缓存恢复。

失败、中断或部分统计缺失时，默认保留待核验。统计接口同时按视频 ID 记录尝试，不能通过重新分组绕过重试限制。检查日志后可显式加 `--retry-failed` 重试一次。第二次仍失败则停止该请求，预算保留两次费用。不会无限重试。

同一个运行目录使用互斥锁。异常退出留下 `.run.lock` 时，先检查其中的进程号，确认没有任务在写该目录，再删除锁并恢复；不要并行使用同一运行目录。
