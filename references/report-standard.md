# 小号爆款报告交付标准

确认日期：2026-10-09。默认交付是有依据的选题解读，不是逐字稿、视频复刻或全平台排名。

## 读者拿到什么

一份可在浏览器打开的图文报告：从本轮已核验的案例中提炼值得借鉴的选题方法，解释具体案例，再给出能迁移到读者内容里的例子。正文保持自然的中文口语；图卡放在对应讲述之后。

顺序：基于真实数据的开场 → 本轮发现 → 1–2 个方法（具体案例、怎么借鉴、跨场景例子、要点）→ 帮读者形成下一条选题的提问/建议。

从本轮充分核验的合格作品中精选至多 3 条，默认提炼 2 个方法。案例或方法不够就少写，不凑数。完整结果池目标是20–30篇；精选达到2–3篇不代表数量达标，少于20篇须明确说明。其余合格作品放在“更多小号爆款”；待核验与有限样本只留在本地原始记录，不对用户展示。没有合格案例时写清本轮结果，不能用待核验条目充当爆款。

## 口吻

- 用户已否定 ASD-STE100 中文适配与 ra-人话 两组改写，继续以 report-example.json 对应的原始样稿为准。以读者能跟着案例理解方法、想到自己的选题为目标，不追求改写幅度、短句数量或禁词命中数。
- 样稿中已经讲清楚的句子可以保留；本轮包含相同案例、相同证据时，可以沿用对应段落，不为了避重而换成抽象说法。不同案例必须依据本轮材料重新解释。
- 直接说具体发现，让用户读懂它和自己有什么关系。例：这两条讲 Skill 的视频，作者粉丝都不到 4000，播放量却都超过了 30 万。
- 接着解释可借鉴的方法。例：它们各有一个值得借鉴的选题思路：一条帮用户挑工具，一条展示普通照片还能变成什么样。
- 用“工具看了很多，轮到自己做科研，还是不知道该装哪个、用在哪一步”这样的具体处境解释案例。
- 把“这个思路怎么借鉴”说到具体选题，允许跨赛道举例；注明这是新选题建议，不冒充原视频内容。
- 不使用“同学们、下午好、今天我们就聊、我帮你筛了一轮”等社群通知或流水账式开场。
- 不输出 qualified、limited、pipeline、框架赋能等内部术语。数据标签统一为“这条作品播放量”“账号正常播放量”。
- 不把每段压成一句抽象结论。先把问题与案例讲明白，再给方法。
- 首先遵循已认可样稿的讲述感：像面对一位创作者解释一件事，使用“工具看了很多，轮到自己用还是不知道选哪个”这样的日常句子。前一句提出的困难，后一句要接着解释，避免一段一段各讲一句总结。
- 每个案例一般用 2–4 个短段把意思讲完：用户卡在哪 → 这个选题怎样回应 → 为什么值得借鉴。原文只需要三句讲清楚时就写三句，不额外补一段分类价值或操作流程来凑长度。
- 原案例中的专业名词只保留理解选题所需的部分。例如讨论科研工具分类，可以写“选题、查资料、绘图、写作、核查”，不必把简介里的产品类别名称全部搬过来。
- 迁移例子中，除本主题的直接借鉴外，优先给一个熟悉的生活或其他内容领域例子，如穿搭、收纳、家居。每个例子说清具体对象和可拍的内容；如果方法不适合跨领域，说明本领域的不同实际用法，不强行类比。
- 事实边界必须保留，但统一放 limitations 和程序的依据说明里。正文需要限定时简短说“从标题和简介看”，不要在每个案例末尾重复一大段免责说明。
- intro 用一到两段接住程序的数据开场，点出读者常见的困难以及案例能给什么启发，不重复汇报搜索流程或逐项报“第一个方法、第二个方法”。
- applications.audience 写简短内容方向（如“AI 自媒体”“摄影”“收纳”），不要写“某某内容创作者”。idea 直接写可拍的选题，不加“新选题建议”“选题方向”等前缀。

- 参考 report-example.json 的句式、展开程度和顺序。沿用文字的前提是本轮证据支持；主题、案例 ID 与统计始终以本轮数据为准。
- 输出纯文本段落，不写 HTML、Markdown 标记、代码块、通知摘要、任务状态或自我评价。

## 数据与视觉

每条图卡展示原封面、原作品标题、作者、采集时粉丝、发布时间、原视频入口、作者主页入口、突出显示的本条播放量、账号正常播放量、相对倍数和按同一比例绘制的对比条形。

“账号正常播放量”沿用同作者邻近作品的中间水平计算口径；原始数据与具体计算说明放在展开区。数值、倍数、开场里的统计和日期全部由程序生成，模型不提交这些字段，也不要在自由段落里自行写播放、粉丝、倍数统计。

原封面属于公开媒体，程序可以在不携带 TikHub Key 的情况下获取并嵌入。封面失败显示清楚的占位与原视频入口，不能用生成图冒充原作品封面。数据不足显示未取得，不能补数字。

## 证据与完成判定

- 标题、简介与已核验数据足以支撑选题、标题包装和迁移建议；完成这些内容后可以交付“选题解读报告”。
- 只有标题与简介时，不允许声称看过视频、引用真实口播、还原镜头或叙事结构。获得真实转写/观看记录后才可写相应细节。
- 精选案例必须已通过内容相关性复核；播放资格与粉丝限制仍由原有程序决定。有限样本与待核验只保留在原始记录，不展示为小号爆款。
- 正文引用、数据指纹、证据指纹、结构与风格校验通过，且有合格的精选案例，才算本版报告完成。未选中的待核验线索只保留在原始记录，不阻塞已有案例的解读。
- 没有合格案例时，只有取数/核验已结束且没有未解决错误或待核验结果，才可完成“本轮未找到”的报告；数据中断不能伪报为没有爆款。
- 已有旧版深度研究报告保持旧判定，不通过改状态把旧报告自动冒充新版交付；需要重新按本格式生成。

## GitHub 交付

把仓库链接交给用户自己的 Agent。Agent 获取仓库、读取 SKILL.md、检查本机运行条件并启动；报告标准、示例、模板随仓库提供。此流程不依赖专门的安装包。后台自动分析必须主动读取本标准与示例，不能依赖当前聊天记忆。

对外声称跨客户端可用前，要区分本机真实验收、离线协议模拟、Windows 模拟测试与 Windows 实机验收。缺依赖、登录或网络时给出具体原因，不挂成无限等待。
